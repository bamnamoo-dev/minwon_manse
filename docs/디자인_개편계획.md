# 민원만세 디자인 개편 계획

작성 2026-11-16 · 상태: 계획 (시안 비교 전)

## 1. 기준: 담당자의 일하는 순서

민원만세는 "민원을 찾아보는 사이트"가 아니라 **민원 한 건을 처리하는 작업 화면**이다.
담당자가 창구·전화에서 실제로 거치는 순서를 화면 구조의 뼈대로 삼는다.

```
찾기 → ① 확인 → ② 안내 → ③ 나이스 처리 → ④ 서식·출력      (+ 근거: 편람 원문·법령)
       발급 가능?   멘트·서류    메뉴 경로·화면     HWP·인쇄
       신원 확인    수수료·기간  단계별 캡처
```

- ③은 지금은 편람의 `process`(처리 과정)만 있고, 나중에 **나이스 민원 사용자매뉴얼** 화면으로 채운다.
  처음부터 이 칸을 비워 둔 구조로 설계해, 추가할 때 화면을 다시 뜯지 않는다.
- 꾸밈보다 위계: 창구에서 한 번 보고 답해야 하는 것(발급 가능 여부·처리기간·수수료·구비서류)이 가장 크게 보인다.

### 1-0. 담당자 답변 (2026-11-16)

- 주로 **민원인을 앞에 두고(창구)** 연다 → 한 화면에서 바로 답할 것만 펼치고 나머지는 접는다.
- 가장 많이 찾는 민원: **학생 민원(생활기록부·재학증명서·졸업증명서)** → 이 세 화면을 기준으로 다듬는다.
- 지금 화면의 불편: **한 화면에 너무 많은 내용이 뜬다** → 카드 나열을 없애고, 처리 과정·법령·처리 정보·서식은 접기로.

### 1-1. 데이터로 확인한 사실 (2026-11-16, 민원 96건)

단일 ①~④ 흐름을 모든 민원에 똑같이 적용하면 빈 칸이 많다. 설계는 이 숫자에 맞춘다.

| 항목 | 해당 민원 | 설계에 주는 의미 |
|---|---|---|
| 처리기간 "즉시" | 43건 | 증명서 즉시 발급형: 확인 → 나이스 발급 → 출력, 빠른 답이 핵심 |
| 그 외(2일~20일 등) | 53건 | 유기한형(학원·법인·교습소 등 인허가·신고): 접수 → 검토 → 처리 → 통보, 서류·서식·법령이 핵심 |
| 연도별 발급경로 규칙 | 28건 | ① 확인(판별기)은 28건에만 등장 → 고정 단계가 아니라 해당 민원에서만 맨 위 |
| 안내 멘트(guideScript) | 0건 | 아직 데이터 없음 → 화면 구조에 칸을 미리 넣지 않음 |
| 서식 | 94건 | 거의 모든 민원 → 서식은 항상 눈에 띄는 자리 |

→ 민원 상세는 **유형 2가지(즉시 발급형 / 유기한형)** 로 배치를 나눈다. 같은 부품을 쓰되 순서와 강조가 다르다.
나이스 매뉴얼도 둘로 나뉜다: 제증명 발급(7~47쪽, 증명서별 발급정보 화면) / 유기한민원 접수·부서 처리(42~58쪽).

## 2. 소스에서 가져오는 시각 언어

AI 템플릿처럼 보이지 않게 하려면 장식이 이 앱의 소재에서 나와야 한다.

| 소재 | 원 소스 | 화면에서 쓰는 방식 |
|---|---|---|
| 번호 표식 ❶❷❸ | 나이스 매뉴얼: 화면 캡처 위에 번호, 아래에 번호별 설명 | 처리 단계 번호와 캡처 위 표식을 **같은 모양**으로 통일. 앱 전체의 핵심 모티프 |
| 메뉴 경로 | 매뉴얼 `메뉴경로 : 민원 〉 민원업무 〉 민원처리 〉 민원접수` | 나이스 처리 단계 머리에 경로 줄로 표시(복사 가능) |
| 쪽 번호 | 편람 인쇄 쪽수, 매뉴얼 쪽수 | 모든 내용 옆에 작은 출처 표기 `편람 129쪽` `매뉴얼 24쪽` — 근거가 보이는 도구 |
| 서식 | 편람 붙임 서식 | 서식 목록은 문서 목록처럼(제목 · 쪽 · 원문/인쇄/HWP) |

## 3. 화면 구조

### 홈 · 검색
- 그라데이션 배너와 "어떤 민원을 찾고 계신가요?" 문구를 없앤다. 검색창이 화면 맨 위의 주인공.
- 결과는 카드 대신 **목록 줄**: 민원명 · 분류 · 처리기간 · 수수료를 한 줄에. 첫 줄은 Enter로 열림.
- 분류는 왼쪽 글자 목록과 건수(배지 없이).

### 민원 상세 = 처리 순서
- 머리: 민원명 + 핵심 정보 한 줄(처리기간 · 수수료 · 신청방법 · 접수처) + 출처 쪽.
- 본문은 ①~④ 단계 구획. 데스크톱은 왼쪽에 단계 목차(스크롤하면 현재 단계 표시), 휴대폰은 위쪽 탭.
  - ① 확인: 발급경로 판별기 · 신원 확인 (지금 오른쪽 사이드바에 있는 것을 첫 단계로)
  - ② 안내: 안내 멘트(복사) · 구비서류 · 담당공무원 확인사항 · 참고사항
  - ③ 나이스 처리: 메뉴 경로 + 단계별 캡처(아래 4장). 자료가 없으면 편람 처리 과정만 표시
  - ④ 서식·출력: 서식 목록
  - 근거: 처리 정보 · 관련 법령 · 편람 원문 보기
- 판별 결과(가능/불가/확인 필요)는 이 앱에서 색을 쓰는 거의 유일한 곳.

### 나이스 처리 안내 (추후 추가 기능, 디자인은 지금 정함)
- 매뉴얼 쪽의 캡처 + 번호 설명을 **캡처 한 장 · 번호 목록** 쌍으로 보여준다.
  - 번호 목록에 마우스를 올리거나 누르면 캡처 위 해당 표식이 강조되고 그 부분이 확대.
  - 나이스 캡처는 글자가 작아 원본 크기 그대로는 못 읽음 → 부분 확대(크롭) 이미지를 기본으로, 전체 보기는 원문 뷰어로.
- 한 민원의 흐름 예(생활기록부): 민원접수(매뉴얼 7쪽) → 제증명민원신청접수(10쪽) → 생활기록부 발급정보(24쪽).
- 데이터는 `data/neis/` 같은 별도 JSON으로 두고 민원 ID와 연결(스키마는 그때 AGENTS.md 규칙 6번대로 validate·계획서와 함께 정함).
  매뉴얼 이미지는 편람 쪽 이미지처럼 스크립트로 뽑는다(`public/neis/`).

## 4. 시각 기준

- 글꼴: Pretendard를 앱에 포함(현재 설정만 있고 파일을 불러오지 않아 맑은 고딕으로 보임). 숫자는 고정폭 숫자.
- 색: 따뜻한 무채색 바탕·잉크색 글자 + 강조색 하나. 빨강·초록·노랑은 판별 결과 전용.
  색은 `ink / muted / line / surface / accent / ok / no / check` 의미 이름으로 정의(파일마다 섞인 gray·slate 정리).
- 모양: 모서리 6~8px, 얇은 구분선. 그림자는 팝업(원문·캡처 확대)에만.
- 줄이는 것: 알약 배지 남발, 색 네모 속 아이콘, 제목 옆 파란 막대, 움직이는 화살표, 키 안내 배지.
- 움직임: 색 변화 정도(0.12초). 인쇄 화면은 지금처럼 유지.

## 5. 진행 순서

화면 로직·데이터·검색은 건드리지 않는다. 단계마다 `npm run validate` + `npm test` + 화면 확인.

1. **현재 화면 캡처** — 개발 서버를 띄워 홈·검색·상세·판별기를 캡처, 문제를 눈으로 확인.
2. **시안 비교(`#/lab`)** — 만듦(2026-11-16). `src/components/Lab.tsx`, 톤은 `src/index.css`의 `.lab[data-tone]`.
   - 주소: `#/lab/M07`(생활기록부) · `M01`(재학) · `M02`(졸업) · `M08`(대입전형용), `?tone=ink|teal|mono`
   - 배치(창구형): 머리(민원명 + 처리기간·수수료·준비물) → ① 누가 왔나요(신원 확인) · ② 주의할 점(편람 참고사항) · 연도별 발급 경로(접힘) | ③ 나이스에서 발급 → 아래쪽 접기: 다른 신청 방법 · 서식 · 처리 정보·법령
   - ③ 예시 데이터: `py scripts/render_neis.py` → `public/neis/`(git 제외). 생활기록부 7→10→24쪽, 재학증명서 7→10→20쪽. 번호 표식 위치는 PDF에서 자동 추출
   - 확인된 문제: 휴대폰 폭에서 **기존 머리글이 넘쳐 화면 전체가 가로로 밀림**(지금 화면도 같음) → D2에서 해결. 머리 3칸 정보도 휴대폰에서는 세로로 쌓아야 함
   - 글꼴: Pretendard 설치가 권한 문제로 보류됨 → 지금 시안은 맑은 고딕으로 보임
   - 담당자 확인(2026-11-16): **시안 디자인(창구형 배치) 확정.**
   - ③ "어디서 발급하나요?"로 변경: 졸업연도(또는 출생연도로 추정)를 한 번 입력 → 연도표 규칙의 `neis`·`certSystem` 칸으로
     **나이스 / 학교증명발급시스템** 중 어디서 발급하는지 판정 → 해당 시스템의 처리 순서 표시. 둘 다 가능하면 둘 다 표시, 둘 다 아니면 "담당 부서 확인"
     (편람에 없는 대체 경로는 지어내지 않음). 정부24·무인발급기·FAX·우편은 같은 입력으로 "다른 발급 경로"(접힘)에 표시
   - 학교증명발급시스템: `py scripts/render_certsys.py` → `public/certsys/`(git 제외). 매뉴얼(2017) 인쇄 6~11쪽 「증명서 발급방법(졸업증명서, 생활기록부)」
     6단계 + 캡처 9장. 화면 속 발급대상 "1951년 2월~2002년 2월 졸업생"이 연도표 규칙과 일치
   - 나이스 연결 추가: 졸업증명서 7→10쪽(공통 접수 화면, 전용 발급정보 화면 없음), 대입전형용 7→10→25쪽
   - 담당자 확인(2026-11-16) — 정식 데이터(`data/`)로 옮길 때 그대로 반영할 것:
     - 매뉴얼 연결 순서 맞음: 생활기록부 나이스 7→10→24쪽, 재학증명서 7→10→20쪽
     - 졸업증명서도 생활기록부·재학증명서와 **같은 방법**으로 나이스 발급(매뉴얼에 전용 화면 없음) → 3번째 화면은 재학증명서 발급정보(20쪽)를 "참고 화면"으로 표시
     - 나이스·학교증명발급시스템 **둘 다 가능한 연도(졸업증명서 1982~2002년 졸업)는 주로 나이스로 처리** → 나이스를 먼저 표시
3. **D0 기준 정리** — 완료(2026-11-16). `src/index.css` 의미 색·A 잉크 톤·모서리, Pretendard 포함.
4. **D1 공통 부품** — `ui.tsx`: Section, Badge, Button, List, 입력칸, 단계 번호 표식(StepMark).
5. **D2 머리글** — 얇은 머리글, 글자 로고, 밑줄 탭 메뉴, 새 파비콘.
6. **D3 검색 화면** — 배너 제거, 목록 줄 결과, 분류 목록.
7. **D4 민원 상세** — 완료(2026-11-16). 시안을 실제 화면으로 옮기고 `#/lab` 시안 화면은 삭제.
   - 즉시 발급형(연도 규칙·매뉴얼 연결이 있거나 처리기간 "즉시"): ① 누가 왔나요 ② 주의할 점 | ③ 어디서 발급하나요 (`src/components/Issue.tsx`)
   - 기간형(인허가·신고): ① 구비서류 ② 주의할 점 | ③ 처리 과정 ④ 서식 / 신원 확인은 접기
   - 매뉴얼 자료를 정식 데이터 `data/manuals/`로 옮김(validate 검사 포함). 단계 목차는 화면이 짧아져 생략
8. **D5 판별기** — 완료(2026-11-16). 카드·색 칸 → 구분선 목록(○△× 기호와 결과 글자만 색), 안내 문구 복사, 신원 확인은 밑줄 선택
9. **D6 업무안내·원문 뷰어** — 완료(2026-11-16). 업무안내는 문서형(읽기 폭 본문), 원문 뷰어는 바탕색 도구 막대·글자 링크. 옛 부품(Badge·Section·Button·List) 삭제
   - 홈 첫 화면은 첫 분류(학생)를 선택한 상태로 연다(담당자 요청). 전체는 주소 c=all
10. **D7 점검** — 휴대폰 폭 375px, 인쇄, 키보드 이동, 글자 대비(AA).
11. (별도 단계) **나이스 처리 안내 데이터** — 매뉴얼 이미지 추출 · `data/neis/` 스키마 · 민원별 연결 · 검수.
