# 민원만세 개발 계획서 (v1.0 · 2026-11-16)

> 서울특별시교육청 「민원편람」(2025 개정판)을 원 소스로, 학교 행정실·교육청 민원 담당자가
> **민원을 검색 → 설명·처리방법·안내멘트·양식**을 한 화면에서 확인하는 종합 민원 검색기.

---

## 0. 결정 사항 요약

| 항목 | 결정 | 이유 |
|---|---|---|
| 형태 | **웹앱(VPS 배포) + PWA(설치형·오프라인 지원)** | 행정실 PC는 인터넷 가능 → 설치 불필요, 업데이트 즉시 반영, 학교 PC의 exe 설치 제한(관리자 권한·보안SW 차단) 회피 |
| 처리 위치 | **검색·계산은 100% 브라우저(로컬)에서** | 서버는 정적 파일만 제공. 출생연도·졸업연도 입력값은 서버로 전송/저장하지 않음 |
| exe | 만들지 않음 (필요 시 PWA "앱 설치" 버튼으로 바탕화면 아이콘 제공) | PWA가 exe와 같은 사용감, 별도 배포·업데이트 문제 없음 |
| 사용자 | 담당자(직원)용 | 로그인 없이 시작(내부 URL), 필요 시 Basic Auth/접속코드 추가 |
| 검색 | 1단계: 키워드·초성·동의어·본문 검색 / 2단계: AI 질의응답(옵션) | 무료·빠름·정확도 우선 |
| 양식 | **HWP 다운로드(있을 때)** + **PDF 원본 페이지 보기/출력(항상)** | HWP가 없는 민원도 편람 원본 페이지로 출력 가능 |

## 1. 원 소스 분석 결과

- `민원편람.pdf` (467쪽), `민원편람.md` (PDF→MD 변환본, `<!-- PAGE: n -->` 마커 포함)
- **주의: MD의 PAGE 번호 = PDF 물리 쪽수**, 목차의 인쇄 쪽수와 약 **+10** 차이 (예: 졸업증명서 목차 129쪽 → `PAGE: 139`). 구간마다 오프셋을 검증할 것.
- 구성
  - II장 민원처리 일반 (접수·처리기간·반복민원·이의신청 등) → **"업무 지식" 문서**
  - III장 민원신청 안내 (즉시/유기한, FAX민원, 정부24, 무인발급기, 우편, 1396, 국민신문고)
    - **47~48쪽 "창구별 발급 가능 연도표"** → 연도별 발급경로 판별기의 핵심 규칙
    - **46쪽 "신청인 신원 확인 방법"** (본인/법정대리인/대리인, 만14세 기준) → 구비서류 판별기
  - IV장 주요 민원처리 업무 안내 (약 21개 주제, 예: 학교시설 사용·사용료표)
  - V장 민원서식 및 신청안내 — **96개 민원**, 모두 동일 틀:
    `사무내용 / 접수처 / 수수료 / 신청방법 / 구비서류 / 처리과 / 공부대조 / 최종결재 / 처리기간 / 관련근거 / 처리과정 / 참고사항 / 붙임 서식`
    - 분류: 학생(14), 교직원(14), 검정고시(12), 유치원(7), 법인(14), 학원(12), 교습소·교습자(8), 평생교육(6), 대안교육기관(3), 기타(5), 영문발급(1)
- **문제점**: MD 변환 시 병합셀 표가 깨진 곳이 많음(특히 연도표·사용료표) → **자동 추출 후 사람 검수 필수**. 연도표 같은 핵심 규칙은 PDF를 보고 손으로 JSON 작성.

## 2. 시스템 구조

```
[개발 PC / 안티그라비티]
  source/민원편람.md, 민원편람.pdf
     │  (Python 추출 스크립트)
     ▼
  data/minwon/*.json   ← 민원 96건 (사람이 검수·수정하는 "진짜 원본")
  data/rules/*.json    ← 연도표·신원확인 규칙 (수작업)
  data/synonyms.json   ← 동의어 사전
  public/pages/*.webp  ← PDF 페이지 이미지 (PyMuPDF로 변환)
  public/forms/*.hwp   ← 확보한 HWP 서식
     │  (npm run build: 검색 인덱스 사전 생성 포함)
     ▼
  dist/ (정적 파일)  ──rsync──▶  [VPS: nginx + HTTPS]
                                        │
                                 [행정실 브라우저]  검색·계산 모두 로컬 / 오프라인 캐시(PWA)
```

- 백엔드 없음(1단계). 2단계 AI 기능 때만 VPS에 작은 API 서버(프록시) 추가.

### 기술 스택 (AI 코딩 도구가 잘 다루는 조합)

| 영역 | 선택 |
|---|---|
| 프론트 | Vite + React + TypeScript + Tailwind CSS |
| 검색 | MiniSearch (또는 FlexSearch) + `es-hangul`(초성 검색·자모 분해) |
| PDF 보기 | 사전 렌더링한 페이지 이미지(webp) + 원본 PDF 해당 쪽 열기(`민원편람.pdf#page=139`) / 필요시 PDF.js |
| PWA | `vite-plugin-pwa` (오프라인 캐시, 바탕화면 설치) |
| 데이터 추출 | Python 3 + PyMuPDF(fitz) |
| 데이터 검증 | zod 스키마 (빌드 시 JSON 형식 오류 차단) |
| 배포 | VPS nginx 정적 호스팅 + Let's Encrypt, `rsync` 배포 스크립트 |

  "notes": ["발급 연도는 졸업 연도를 의미함(출생 연도 X)"]

> ⚠ MD 변환본은 47쪽 표의 열 이름이 어긋나 있음("증명발급시스템" 열이 "교육기관"으로 잘못 붙음).
> 실제 PDF 기준: 1951~2002년 졸업자는 **증명발급시스템(교육기관 방문)**으로 발급, FAX민원(교육기관·구청·주민센터)은 연도 제한 없이 ○.
> 실제 파일: `data/rules/issuance_years.json` (채널 8개: neis, certSystem, faxEdu, faxGu, mail, gov24Online, gov24Mail, kiosk)

### 3-3. 기타
- `data/rules/identity.json`: 본인/법정대리인/대리인 × 만14세 기준 구비서류 (46쪽)
- `data/guides/G01~G37.json`: II·III·IV·VI장 업무 지식 문서 (검색 대상에 포함)
- `data/forms_files.json`: 민원 ↔ 서식 파일(`public/forms/` hwpx·pdf) 연결. 편람 서식 이름(forms[].name)과 같으면 그 서식에 HWP·PDF를 붙이고, 아니면 추가 서식으로 표시. `common`(위임장 등)은 여러 화면 공통
- `data/manuals/`: 발급 시스템 매뉴얼 — `links.json`(민원 ↔ 나이스 매뉴얼 쪽·학교증명발급시스템 절차 연결, 사람이 관리), `neis.json`·`certsys.json`(매뉴얼 PDF 자동 추출: 화면 캡처·번호 표식 위치·번호별 설명 / 단계별 설명·캡처). 민원 상세 「어디서 발급하나요?」에서 연도표 규칙(neis·certSystem 칸)으로 시스템을 판정한 뒤 해당 처리 순서를 보여준다
- `data/synonyms.json`: `{"생기부": "학교생활기록부", "성적표": "성적증명서", "검시": "검정고시", "학원등록": "학원 설립·운영등록", ...}`

## 4. 주요 화면·기능

### MVP (1단계)
1. **통합 검색창** (첫 화면 중앙)
   - 제목 검색, 초성 검색(`ㅈㅇㅈㅁㅅ` → 졸업증명서), 동의어, 본문(사무내용·참고사항) 검색
   - 결과에 카테고리·처리기간·수수료 미리보기
   - 카테고리 탭(학생/교직원/검정고시/학원 …) 둘러보기
2. **민원 상세 페이지**
   - 요약 카드: 접수처 / 수수료 / 처리기간 / 구비서류
   - 처리과정(채널별 단계 흐름도)
   - **민원인 안내 멘트 [복사] 버튼** (전화·창구 응대용)
   - 관련 법규, 참고사항
   - **양식**: HWP 다운로드(있을 때) · **PDF 원본 페이지 보기/인쇄**(항상)
   - "편람 원문 보기"(해당 쪽 이미지) — 데이터 오류 시 원문 확인용
3. **연도별 발급경로 판별기** ⭐ (가장 큰 실무 가치)
   - 입력: 증명서 종류 + 졸업연도(또는 출생연도 → 졸업연도 추정)
   - 출력: "이분은 **NEIS 불가 / 교육기관 FAX 민원으로 발급**, 정부24 불가" 같은 경로별 가능/불가 표
   - 출생연도 입력 시 "고졸 기준 추정 졸업연도 = 출생+19 (빠른년생·유급·검정고시 등 예외 있음, 반드시 확인)" 경고
4. **구비서류 판별기**: 방문자(본인/법정대리인/대리인) × 대상자 나이 → 필요 서류 체크리스트
5. **업무 지식 검색**: II~IV장 문서(반복민원 처리, 이의신청, 처리기간 계산 등)
6. 즐겨찾기·최근 본 민원 (브라우저 localStorage)
7. 편람 버전·기준일 표시 + "관계 법령 개정 시 법령이 우선" 면책 문구

### 2단계
- AI 질의응답: "할머니가 1975년 졸업장을…" → 관련 민원 + 판별기 결과 + 근거 쪽수 제시 (VPS 프록시로 Gemini/Claude 호출, 근거는 편람 데이터만 사용 — RAG)
- 오류 제보 버튼 (담당자가 틀린 내용 신고 → 관리자 확인)
- 간단한 관리자 편집 화면 (JSON 직접 수정 대신)
- 기관 메모(우리 학교만의 팁) 공유

## 5. 개발 단계 (안티그라비티 작업 순서)

> 각 단계는 "에이전트에게 줄 지시문" 단위로 나눔. 한 단계 끝날 때마다 직접 확인 후 다음 단계 진행.

### Phase 0. 프로젝트 셋업 (0.5일)
- 폴더 구조 생성, `git init`, Vite+React+TS+Tailwind 초기화
- 원본 파일을 `source/`로 이동 (원본은 수정 금지)
```
minwon_manse/
  source/        민원편람.md, 민원편람.pdf (읽기 전용)
  scripts/       extract_minwon.py, render_pages.py, validate.ts
  data/          minwon/, rules/, guides/, synonyms.json
  public/        pages/, forms/
  src/           React 앱
  docs/          이 계획서, 데이터 검수 체크리스트
```

### Phase 1. 데이터 추출 (2~3일, 가장 중요)
1. `render_pages.py`: PDF 467쪽 → `public/pages/p{n}.webp` (폭 1200px)
2. `extract_minwon.py`: MD에서 `## n) ○○ 신청` 단위로 96건 분리 → 표 파싱 → JSON 초안
3. 파싱 실패 필드는 `"_raw"`에 원문 보관, 리포트 출력
4. 연도표(47~48쪽)·신원확인표(46쪽)는 **수작업 JSON** (AI에 PDF 페이지 이미지를 보여주고 초안 → 사람 검수)
5. zod 스키마로 검증
- **완료 기준**: 96건 JSON 생성, 검증 통과, 랜덤 10건을 PDF와 대조해 오류 0

### Phase 2. 검색 MVP (2일)
- 검색 인덱스 빌드 스크립트(빌드 시 사전 생성) + 초성·동의어
- 검색 화면, 카테고리 탭, 상세 페이지
- **완료 기준**: "생기부", "ㅈㅇㅈㅁ", "학원 등록", "폐교 졸업" 검색 시 기대 결과가 1~3위

### Phase 3. 판별기 (2일)
- 연도별 발급경로 판별기, 구비서류 판별기
- 규칙 단위 테스트(Vitest): 경계값(2002-02, 2003-02, 1982-02, 1951-02) 필수
- **완료 기준**: 테스트 전부 통과 + 47~48쪽 표 모든 행 대조

### Phase 4. 양식·원문 (1일)
- 상세 페이지 양식 영역: HWP 링크 / PDF 원본 페이지 보기 / 인쇄(`@media print`로 해당 쪽 이미지만 출력)
