## 1. 지금까지 한 일 (순서대로)

- 추출기 개선: 서식 쪽을 서식별로 분리(M96 영문 20종+참고 3종), 빈 쪽·목차 쪽 제외, 구비서류를 신청서 '제출서류'란에서 보충(27건), 담당공무원 확인사항 추출, **덮어쓰기 보호**(reviewed 또는 사람이 수정한 파일은 재추출 시 건너뜀 — `_genHash`로 감지)

### Phase 2 — 검색 화면
- 검색 엔진 `src/lib/search.ts`: 초성(ㅈㅇㅈㅁ), 동의어(`data/synonyms.json`: 생기부·졸업장·과외 등 약 50개), 두 글자 조각 부분일치, 분류 필터, 제목 적합도 가산
- 화면: 검색/분류 둘러보기, 민원 상세(요약·구비서류·처리과정·참고사항·서식 원문 보기/인쇄/HWP 자리), 업무안내, 편람 원문 페이지 뷰어(인쇄 가능)

- `scripts/build_data.ts` → `public/data/bundle.json`(약 474KB, git 제외, dev/build 전에 자동 생성)

### Phase 3 — 판별기
- `src/lib/judge.ts` + 화면 `src/components/Judge.tsx` (`#/judge`, 제증명 민원 상세에도 내장)

## 2. 발견한 원본 데이터 문제 (알고 있어야 함)

1. **MD 변환 오류**: 병합셀 표에서 칸이 밀림(예: 47쪽 "증명발급시스템" 열이 "교육기관 FAX"로 잘못 붙음). **기준은 항상 PDF.**
2. **MD에서 14쪽 분량 내용이 통째로 빠짐**(22, 30, 34, 110, 191~193, 269, 354, 373~374, 392, 415, 417쪽) → PDF 텍스트로 보충(`pdfTextPages` 필드)
3. **쪽 번호**: JSON의 쪽 = PDF 물리 쪽 = 인쇄 쪽 + 10
4. 편람 내부 불일치: 검정고시 무인발급(1978 vs 1983), 재학증명서 정부24(요약표 vs 48쪽 표), M61 붙임 서식명 오기("용도변경" 공문)
5. 수수료는 96건 모두 "없음"
6. 구비서류 목록이 편람에 아예 없는 민원 18건(주로 법인 공문) → 신청서 이름만 넣고 "편람에 별도 목록 없음" 표시

## 4. 다음 할 일 — Phase 6 배포 (안티그라비티에서 진행)

### 결정된 것
- VPS에 **정적 사이트**로 배포 (서버 프로그램 불필요, nginx 등으로 `dist/` 제공)
- **접속 제한 없음**(누구나 접속), 단 검색엔진 수집 차단(이미 `index.html`에 `noindex` 있음)
- 서버 정보(OS, 도메인, nginx/Docker 여부)는 **사용자가 안티그라비티에서 제공**

### 할 일 체크리스트
1. **PWA 적용** (바탕화면 설치·오프라인)
   - `vite-plugin-pwa@1.0.1` (vite 6 호환 확인됨) 설치, `vite.config.ts`에 추가
   - manifest: 이름 "민원만세", short_name "민원만세", 테마색 `#1d4ed8`, 아이콘 192/512 PNG(현재 `public/favicon.svg`만 있음 → PNG 생성 필요)
   - 프리캐시: 앱 파일 + `data/bundle.json` / 런타임 캐시(CacheFirst): `pages/*.webp`, `forms/*`
   - `registerType: "autoUpdate"` — 새 배포 시 데이터 자동 갱신
   - **HTTPS가 있어야 PWA가 동작**함(도메인+인증서 필요, IP 접속이면 PWA 생략)
2. **(하위 경로 배포 시)** `vite.config.ts`의 `base`를 예: `"/minwon/"`로. 코드는 이미 `import.meta.env.BASE_URL` 사용 중
3. `public/robots.txt` 추가: `User-agent: *` / `Disallow: /`
4. **nginx 설정**
   - `root` → 업로드한 `dist` 폴더, `try_files $uri $uri/ /index.html;`
   - 캐시: `assets/*` 1년 immutable / `index.html`, `sw.js`, `data/bundle.json`은 `no-cache` / `pages/*.webp` 30일
   - gzip(json·js·css), `X-Robots-Tag: noindex`
   - HTTPS: Let's Encrypt(certbot)
   - 참고: 검색어는 URL 해시(#) 뒤에 있어 **서버 로그에 남지 않음** — 해시 라우팅을 바꾸지 말 것
5. **배포 스크립트**: `npm run build` → `dist/`를 서버로 업로드(rsync 또는 scp). Windows라 rsync가 없을 수 있음
6. 배포 후 확인: 첫 화면·검색·상세·판별기·원문 이미지·인쇄, 휴대폰, (PWA면) 설치·오프라인

### 그 이후 (계획서 기준)
- **데이터 검수**: `docs/검수_체크리스트.md` 2순위(학생 M01~M14, 인사 M15~M20, 검정고시 M29~M40)부터. 끝난 파일은 `"reviewed": true`

- (선택) Phase 8 AI 질의응답

## 5. 안티그라비티 에이전트에게 지킬 것 (요약 — 자세한 건 AGENTS.md)

1. `source/`는 절대 수정 금지. 민원 내용은 `data/` JSON에서만 읽고 코드에 하드코딩 금지
2. **편람에 없는 내용을 지어내지 말 것** — 모르면 `TODO(검수필요)` 표시 후 사람에게 묻기
3. `"reviewed": true` 데이터와 사람이 고친 데이터는 임의로 바꾸지 말 것. `npm run extract -- --force` 금지(사용자 허락 시만)
4. 사용자가 입력한 연도·나이·생년월일은 **브라우저 밖으로 보내지 않기**(URL·localStorage·서버 금지)
5. 검색이나 판별 로직을 바꾸면 `npm test` 통과 확인. 규칙 JSON 수정 시 경계값 테스트도 갱신
6. `useEffect(() => window.scrollTo(...))` 같은 값 반환 축약형 금지(최신 브라우저에서 React 오류)
7. 작업은 Phase·파일 단위로 작게, 끝날 때마다 `npm run build` + 화면 확인 + git 커밋
